# Подсветка места в источнике — спека W3b-2

Статус: **реализовано** (2026-10-24). Шаги §9 закрыты; открытые вопросы §11 решены
рекомендованными вариантами (см. §12).
Родительский план — `.cursor/plans/answer-quality-max-pro.md` (волна W3b, часть 2).

## 1. Задача

Панель цитат (W3b, часть 1) показывает дословный `quote` и честную подпись места
(«Стр. 4» / «Символы 120–180» / «точное место недоступно»). Пользователь не может
**увидеть это место в тексте источника** — ему остаётся доверять цитате или открыть файл
целиком и искать глазами.

W3b-2 добавляет ровно это: клик по цитате открывает фрагмент распарсенного текста
вложения с подсвеченным диапазоном. Всё, что нельзя подсветить достоверно, остаётся
честным «недоступно» — «подсветить примерно» запрещено (055).

## 2. Что уже есть (факты из кода, не предположения)

| Факт | Где |
|---|---|
| `CitationRef` несёт `source_ref` (имя файла или URL), `quote`, `page`, `source_range`, `answer_range`, `anchor` | `domain/content/citations/models.py` |
| `citations` в `DocumentMeta` — `SkipJsonSchema`: есть на проводе server → client, нет в strict-схеме провайдера | `domain/content/content_document.py` |
| Якоря прикрепляются после валидации документа; блоки к этому моменту уже отрисованы | `FormatterAgent._run_schema_first` |
| Распарсенный текст вложения персистится как `AttachmentContent.safe_text` (`derived_text_key` в blob) | `domain/attachments/content.py`, `attachment_service._read_content` |
| `safe_text` — это ровно тот текст, который ушёл провайдеру, **без** наших `[[page N]]` (маркеры пишутся в `parsed.text`, а не в `flow_text`) | `attachment_pipeline.py` (`_content_outcome` ← `prepared.text`) |
| При `scan.action="mask"` и `PII_POLICY=mask` `safe_text` — редактированный вид (смещения согласованы с ним, не с исходником) | `attachment_pipeline.py` (`mask_pii_in_text`) |
| PII-редактирование **не** меняет `scan.action`: после маски PII действие остаётся `allow`, поэтому «текст отредактирован» из `scan.action` не выводится | `attachment_pipeline.py` (`_content_outcome`, `summary.action=prepared.action`) |
| Перед отправкой текст оборачивается в fence, а на длинных ходах ещё и обрезается head+tail (`budget_untrusted_text`) | `domain/policies/untrusted_content.py` |
| `source_ref` строятся из fence-заголовков: `attachment:<uuid>:<filename>`; при одноимённых загрузках добавляется `#id8` | `domain/attachments/citations.py` |
| У клиента текста источника нет; панель цитат осознанно не делает переход | `web/src/components/CitationSources.tsx` |
| Вложение читается только владельцем: `service.get(..., user_id=principal.subject)`, таблица под `FORCE RLS` | `presentation/api/routers/attachments.py`, 060 |

Вывод: **координатного пространства, общего у провайдера и сервера, ровно одно** —
`safe_text`. Оно воспроизводимо (хранится), оно же было отправлено провайдеру (до
обёртки в fence и до бюджетной обрезки). Всё остальное — PDF-координаты, страницы
просмотрщика, `parsed.text` с нашими маркерами, сырой ответ LLM — другими пространствами.

## 3. Ключевые решения

### 3.1 Источник истины — `quote`, а не смещение

`source_range` приходит от провайдера и может быть смещён относительно `safe_text`:
fence-заголовок добавляет префикс, `budget_untrusted_text` вырезает середину
(head+tail), provider-специфичные форматы считают по-своему. Поэтому смещение —
**подсказка**, а не доказательство.

`quote` — дословный фрагмент того самого текста, который был у провайдера. Поиск цитаты
детерминирован, не требует LLM и переживает сдвиг смещений. Отсюда политика:

```text
declared  = source_range, если anchor == "char_location"  (иначе None)
verified  = declared и normalize(safe_text[declared]) ⊇ normalize(quote) либо ⊆ normalize(quote)
candidate = первое уникальное вхождение normalize(quote) в normalize(safe_text)
```

| Исход | Условие | Что показывает UI |
|---|---|---|
| `declared_range` | `verified` | подсветка `declared` |
| `quote_match` | `declared` не прошёл, `candidate` уникален | подсветка найденного вхождения |
| `ambiguous_quote` | вхождений ≥ 2 | «точное место недоступно», без подсветки |
| `quote_not_found` | вхождений 0 | «точное место недоступно» |
| `no_text` | `safe_text` пуст (не распарсилось) | «текст источника недоступен» |

Нормализация — `normalize_for_match` из `domain/content/citations/normalizer.py`
(collapse whitespace): сравнивать «как есть» нельзя, провайдеры переписывают переносы.
Функция переиспользуется, а не дублируется: два разных определения «того же текста»
разошлись бы на первом же неразрывном пробеле (010).

### 3.2 Что НЕ является основанием для подсветки

- `anchor="content_block_location"` — это индексы блоков, а не символы; адаптер кладёт их
  в `source_range` (`infrastructure/llm/citation_mapping.py`, ветка
  `content_block_location`). Подсветка по ним адресовала бы случайный фрагмент →
  только quote-поиск.
- `answer_range` — смещение в сыром ответе LLM; после `schema_first` документ пересобран,
  подсветка по нему адресует не то место.
- `url_only` — внешнюю страницу мы не контролируем; остаётся ссылка, без подсветки.
- `page` без `source_range` — подсветить страницу целиком нельзя (нет постраничных
  смещений в `safe_text`); показывается подпись «Стр. N», как сейчас.

### 3.3 Где это живёт

Поиск — **чистая доменная политика**, без I/O и без LLM (055):
`domain/content/citations/locate.py`, `CitationLocator.locate(text, quote, declared_range)`.
Её вызывают use-case и тесты; роутер ничего не решает, кроме прав и лимитов.

## 4. Контракт

### 4.2 `AttachmentContent.text_masked` (новое аддитивное поле)

Чтобы честно ответить «этот текст отредактирован», нужен факт, а не догадка:
`scan.action == "mask"` покрывает только injection-редактирование, а PII-маска
(`PII_POLICY=mask`) текст меняет, оставляя `action="allow"`.

```python
# domain/attachments/content.py
class AttachmentContent(BaseModel, frozen=True):
    ...
    #: ``safe_text`` отличается от извлечённого текста (injection-редакция или PII-маска).
    text_masked: bool = False
```

- Заполняется в `_content_outcome` при записи: `prepared.action == "mask" or pii.mode == "mask"`.
- Default `False` — старые блобы читаются без миграции (поле аддитивное).
- Выводить признак из текущего конфига PII на чтении **нельзя**: политика могла
  измениться после записи, и тогда UI соврёт про уже сохранённый текст.

### 4.3 `CitationRef.source_id` (новое поле)

```python
# domain/content/citations/models.py
source_id: str | None = Field(default=None, max_length=36)  # UUID вложения в текстовом виде
```

- Тип — строка, не `UUID`: модель цитат остаётся сериализуемой в JSON без спец-энкодеров,
  а значение всё равно проверяется на стороне сервиса.
- Заполняется **сервером**, никогда моделью: `citations` уже вне strict-схемы
  (`SkipJsonSchema`), так что поле не «обязательно для провайдера».
- Правило заполнения (инвариант уникальности): источник получает `source_id`, только если
  fence-заголовки хода содержат **ровно одно** вложение с таким `source_ref`
  (с учётом `#id8`, если он есть). Два файла с одним именем → `source_id=None`: выбор
  «какой из них» — догадка, а догадка здесь хуже отсутствия.
- Кто заполняет: `FormatterAgent._resolve_citations` получает карту
  `label → attachment_id` из `task_input.context_packet.untrusted_context`. Парсер уже есть
  (`citation_refs_from_untrusted_context`) — из него выделяется функция
  `attachment_ids_by_label(...)`, чтобы метки совпадали по построению, а не «похоже».

### 4.4 Endpoint

```http
POST /api/attachments/{attachment_id}/citation-locate
Content-Type: application/json

{
  "quote": "Оплата в течение 5 рабочих дней",
  "source_range": [1200, 1237],
  "anchor": "char_location"
}
```

Почему POST: `quote` — фрагмент конфиденциального документа. В query string он попал бы
в access-логи прокси и в историю; тело запроса там не оседает (020). Побочных эффектов
нет — метод выбран из-за payload'а, а не из-за мутации.

Ответ `200`:

```json
{
  "attachment_id": "…",
  "filename": "Договор.pdf",
  "outcome": "quote_match",
  "start": 1188,
  "end": 1225,
  "window_start": 900,
  "window_end": 1600,
  "text": "…фрагмент источника вокруг найденного места…",
  "total_chars": 24110,
  "text_state": "full"
}
```

- `start`/`end` — абсолютные смещения в `safe_text` (не в окне): клиент подсвечивает
  `[start - window_start, end - window_start)` и не пересчитывает их сам.
- `outcome` — закрытый набор из §3.1 (`declared_range` / `quote_match` / `ambiguous_quote` /
  `quote_not_found` / `no_text`). При `ambiguous_quote`/`quote_not_found`/`no_text`
  `start`/`end` — `null`, окно всё равно отдаётся (пользователь видит контекст и понимает,
  что подсветки нет).
- `text_state` — `full` | `masked`, из `AttachmentContent.text_masked` (§4.2). Подпись в UI
  обязательна: пользователь должен знать, что читает отредактированный вид.
- `window_*` ограничены константой `CITATION_WINDOW_CHARS = 2000` в `core/types`
  (±`CITATION_WINDOW_PAD = 300` вокруг диапазона); окно никогда не «весь документ»,
  иначе endpoint становится выгрузкой файла в обход `download`.

Коды ошибок: `404` — нет такого вложения или чужое (не различаем: иначе это оракул
существования, 020); `409` — вложение не в состоянии с текстом (quarantined/rejected/
expired, `rejection_reason` в детали); `422` — `quote` пустой или длиннее лимита.

Лимиты: `quote ≤ 2000` символов, тело запроса ≤ 8 КБ (стандартный лимит приложения),
`window ≤ CITATION_WINDOW_CHARS`. Окно — единственный тяжёлый ответ, и оно ограничено.

### 4.5 Use-case

`AttachmentService.locate_citation(attachment_id, user_id, quote, declared_range, anchor)`:

1. `_require(...)` — владелец (RLS + явный фильтр, 060);
2. `_read_content(...)` — `AttachmentContent`; нет ключа/блоба → `409`;
3. `CitationLocator.locate(content.safe_text, quote, declared)` — политика;
4. окно вокруг результата, `text_state = "masked" if content.text_masked else "full"`;
5. audit-событие `attachment_citation_located` (без текста и без quote: только длины и
   `outcome`).

## 5. UI

- В панели цитат у каждой записи появляется действие «Показать в источнике» **только** если
  `citation.source_id` не `null`. Нет `source_id` — действие не рендерится (не disabled:
  кнопка, которая всегда падает, хуже её отсутствия).
- Панель источника — отдельная область под панелью цитат (не модал: цитаты и контекст
  должны читаться одновременно). Внутри: имя файла, пометка «текст отредактирован» при
  `text_state="masked"`, текст окна, `<mark>` на найденном диапазоне.
- Состояния: `loading` (кнопка `aria-busy`), `resolved` (подсветка + перевод фокуса на
  `<mark>` через `tabIndex={-1}` и `focus()`), `unavailable` (три разных текста по
  `outcome`, без подсветки), `error` (retry).
- Escape закрывает панель источника раньше, чем панель цитат (вложенность). Слушатель
  снимается вместе с закрытием (080).
- i18n: `cite.showInSource`, `cite.sourcePanel`, `cite.sourceMasked`,
  `cite.sourceAmbiguous`, `cite.sourceNotFound`, `cite.sourceNoText`, `cite.sourceError` —
  в оба словаря (`web/src/i18n/messages.ts`), тест `noEnglish` в матрице состояний ловит
  пропуск.
- Никаких сетевых запросов до клика: панель цитат остаётся дешёвой (W1/TTFVF не трогаем).

## 6. Метрика

Одно новое имя, в реестре 040: `palatium_citation_highlight_total{outcome}` —
знаменатель = все запросы подсветки, включая неудачные (иначе rate улучшается
отказом от сложных кейсов — та же ошибка, что была исправлена в W0b).

## 7. Безопасность

- Только владелец: `principal.subject` + RLS-политика на `palatium_ai.attachments`.
- `quote` — в теле, не в URL; не логируется (audit пишет `outcome` и длины).
- Ответ источника — `Cache-Control: no-store`.
- Отредактированный (`masked`) текст отдаётся как есть, без «раскрытия» оригиналов:
  оригинал доступен только через `download` с presigned URL.
- Никакой новой внешней зависимости и ни одного LLM-вызова: политика чистая.

## 9. Порядок работ

1. `CitationLocator` + тесты (чистая политика, без API и UI).
2. `AttachmentContent.text_masked` + тесты (без него §4.4 не может сказать правду).
3. `CitationRef.source_id` + `attachment_ids_by_label` + тесты (контракт цитаты).
4. `AttachmentService.locate_citation` + endpoint + тесты прав/лимитов.
5. Метрика `palatium_citation_highlight_total` + обновление реестра 040.
6. UI: `SourcePanel`, кнопка в `CitationSources`, i18n, web-тесты.
7. E2E + запись в `docs/formatter-schema-first.md` и `docs/runbook.md` (эксплуатация).

Шаги 1–4 самостоятельны: без UI они дают проверяемый контракт и ноль изменений в
пользовательском пути.

## 10. Что сознательно не делаем

- Подсветка в тексте **ответа** по `answer_range` — не адресует отрисованные блоки.
- Координаты PDF/страницы просмотрщика — другая система координат; потребует pdf.js и
  собственной спеки, это не «добавить кнопку».
- Подсветка для `url_only` источников — чужую страницу мы не контролируем.
- LLM-поиск «похожего места» — недетерминированно и врёт тихо.

## 11. Открытые вопросы (решение за владельцем)

1. **Форма endpoint'а.** POST с `quote` в теле (рекомендация) против GET с `start/end` и
   проверкой цитаты на клиенте. Второй вариант дешевле по трафику, но клиент не имеет
   полного текста, поэтому quote-поиск на нём невозможен — и «сдвинутые» смещения не
   исправляются.
2. **Показывать ли `masked`-текст.** Рекомендация: да, с явной подписью (пользователь
   читает свой же документ в отредактированном виде). Альтернатива — не открывать панель
   для `masked` вовсе; тогда подсветка пропадает ровно там, где она нужнее.
3. **Размер окна.** `2000` символов (±300) — оценка; нужен замер на реальных документах
   (`tests/perf` не требуется, достаточно ручного прогона на 5 файлах).
4. **Вложения режима `index`.** Текст есть, но файл живёт в knowledge-контуре. Показывать
   подсветку по нему или ограничиться `mode=attach`? Рекомендация: только `attach` —
   у `index` владелец может не совпадать с читателем ответа.

## 12. Решения, принятые при реализации (2026-10-24)

1. **POST** `…/citation-locate` с `quote` в теле. Кавычки не попадают в access-логи
   прокси и историю браузера; побочных эффектов нет, поэтому POST — про тело, не про
   мутацию (020).
2. **`masked` показывается** с подписью «Текст источника показан с редактированием»:
   подсветка нужна именно там, где текст нельзя вернуть дословно, а молчание выдало бы
   отредактированный вид за оригинал.
3. **Окно 2000 символов, пад 300** — в `core/types/citations.py`; ответ **всегда**
   bounded: если пришедший извне span длиннее окна, срез начинается со span (подсветка
   не уезжает за левый край), а размер ответа не зависит от щедрости клиента.
4. **Режим вложения не фильтруется на endpoint'е**, а ограничен тем, что владелец
   видит только свои строки (`WHERE user_id`, FORCE RLS). Дополнительный фильтр по
   `mode` скрыл бы цитату из `index`-файла, которую пользователь только что получил в
   ответе, — то есть спрятал бы доказательство.
5. **`source_id` — не контракт провайдера.** Поле живёт в `CitationRef` вне strict-схемы
   и заполняется после валидации документа (`_bind_source_ids`), поэтому модель не может
   его выдумать.
6. **Клиент не ищет текст** и не пересчитывает смещения: сервер отдаёт `start`/`end`
   в координатах `safe_text` вместе с `window_start`; UI только вычитает начало окна.
7. **`text_masked` фиксируется при записи**, а не выводится из текущей
   конфигурации при чтении: блоб писался под другой политикой, и пересчёт описал бы не
   его (060).

Изменения контракта, которые спека не предполагала заранее:
`AttachmentCitationLookup` (`domain/attachments/citation_lookup.py`) — доменная модель
среза; `CitationLocator.locate` принимает `anchor` и по умолчанию `char_location`
(`content_block_location` не даёт смещения); `citation_refs_from_untrusted_context` и
`attachment_ids_by_label` строят метки **одним** кодом (`_labelled_fences`), иначе чип и
открываемый файл могли разойтись.
