# Алгоритм миграции агента

При противоречии этой инструкции и правил — правила (индекс: 099).

Если миграция/рефакторинг ведётся по исходному черновику «RAG-система с
агентной памятью» (7 агентов, LangMem+Cognee, ParadeDB и т.д.) — сначала
прочитай [reference.md](reference.md): там сведено, что из черновика уже
принято правилами 000–099, что заменено более поздним решением, и какие
пункты требуют явного ответа пользователя перед реализацией. Черновик сам
по себе — не источник контрактов; при расхождении с ним побеждают правила.

1. Прочитай legacy-файл `application/agents/<name>_agent.py`.
2. Создай пакет `application/agents/<name>/`: `__init__.py`, `agent.py`,
   `prompts.py`, `config.py`, `evals/`.
3. Перенеси промпты → `prompts.py`; параметры → pydantic `AgentConfig`
   в `config.py`. **Состав полей и типы — только по контракту 030** (не копируй
   перечень из этого скилла); значения timeout/retry/threshold — из settings/
   config.py (050: никаких литералов, зашитых из скилла).
4. Класс наследует `BaseAgent`; реализуй методы по контракту 030
   (`run`, `get_required_context_keys`, `get_available_tools`, `verify`).
5. Замени прямые вызовы LLM/БД →`execute_with_guardrails`** (единая точка,
   порт `domain/ports/harness.py`, 065). Прямой `self.harness.llm` — запрещён.
   Узел получает данные JIT-ключами (input_keys, 065).
6. Confidence: порог и стратегия — часть CriticPolicy (055, закрытый перечень);
   агент НЕ изобретает self-grade без grader (075). Низкий confidence →
   `status="partial"` + эскалация через HITL (020), не тихий возврат.
7. Unit-тесты + `evals/tasks.json`: кейсы проектируй от behavior и grader-покрытия
   (075), не «минимум N штук».
8. Обнови импорты и регистрацию: реестр агентов — единый источник 000
   (проверь, что скилл не вводит нового агента мимо реестра); граф —
   `orchestration/nodes.py`.
9. Удали legacy-файл. Grep по старому имени: битых импортов нет.
10. Особый случай: ContextWeaver+Contextualizer → `context_enricher/` —
    по инвариантам 055: ось `continuation_kind` → в enricher, `task_kind` —
    остаётся в Intent. Оси не смешивать (055 — источник, не пересказ).

## Инварианты при миграции (не потерять)

- Supervisor: только plan/delegate/review в allowed_tools. НИКОГДА не исполняет.
- Трассировка на каждом узле графа (040); метрики — только из реестра
  `palatium_*` (040) на значимые события, не «на каждый узел».
- Контракты осей Continuity/Intent/Critic — источники 055; не сломать при слиянии.
- AgentConfig — pydantic, без `Any` (010); поля — по 030, значения — из config.
